# checkpoint

**Summary:** Prepare for a level checkpoint: a short knowledge check, then feedback on your evidence.
**Options:** `checkpoint <1-4>` · `--quiz` (knowledge check only) · `--evidence` (evidence review only)
**Examples:** `checkpoint 1` · "Am I ready for the Level 3 checkpoint?" · `checkpoint 2 --evidence`
**Next:** `next`, `explain`

## Fetch
1. The checkpoint module `L<n>.C` page (link in the agent index): prerequisites, practice, evidence, projects.
2. The level page (link in the agent index): the level's outcome, checkpoint task and evidence list.
Don't fetch the individual module pages; the module index outcomes are enough for questions.

## 1. Readiness
List the checkpoint's prerequisites. Ask which are done if you don't know; name any missing ones.

## 2. Knowledge check (skip with `--evidence`)
- Five questions built from the outcomes of that level's modules in the module index, mixing multiple choice and short scenario questions. At least one question on safe use, and for Levels 3-4 one on the autonomy dial.
- Ask one at a time if the learner prefers; otherwise all five, then grade together. If an interactive quiz tool is available in this app, you may use it.
- For each answer: right or not, a one-line explanation, and the module ID it comes from.
- Summary: score, and the modules to revisit (`ID · Title`).

## 3. Evidence review (skip with `--quiz`)
- Show the level's evidence list from the level page.
- Invite the learner to paste or describe their evidence. Remind them to remove customer data, personal data and secrets first.
- Give feedback item by item: present / partly / missing, and what would make it stronger.

## Always say
"This is practice. The level counts as complete only after a mentor or peer reviews your checkpoint, as the roadmap requires." (Levels 3-4: a mentor.) Never state or imply the level is passed.

End with: "Next: `next`" (gaps to fill) or "share your evidence with a reviewer" (ready).
